Overview
--------
N112 transforms evidence distribution from a pull-based model
(MissingEvidenceRequest/Response) to a push-first model.  Peers
proactively push EvidenceRecords to each other, eliminating the
round-trip delay of the pull protocol.

After N112, a node that receives a SlashingCertificate with unknown
evidence IDs can still fall back to MissingEvidenceRequest, but
in the common case the evidence arrives via push before the
certificate is even received.

Known Issues
------------
1. Push is fire-and-forget.  There is no acknowledgment or
   retransmission protocol.  If a push message is lost, the
   receiving node will fall back to MissingEvidenceRequest.

2. EvidencePushMessage carries full serialised EvidenceRecords
   (Vec<Vec<u8>>).  Large evidence payloads may benefit from
   a chunked transfer protocol.

3. Validator identity mapping (32-byte → 48-byte PublicKey)
   remains the temporary zero-pad solution from N110.1b.
