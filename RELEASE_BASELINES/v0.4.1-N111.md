Overview
--------
This baseline captures AmunChain after the evidence propagation layer
was completed.  Before N111, evidence records were local to each node.
A SlashingCertificate referencing unknown evidence IDs would be
rejected, breaking deterministic slashing across the network.

N111 closes this gap by introducing:

  - EvidenceAnnouncement — a lightweight network message that notifies
    peers about new evidence.
  - EvidenceGossip — a deduplication and broadcast-tracking layer.
  - Transport integration — EvidenceAnnounce added to the consensus
    NetworkMessage and EvidenceAnnouncement to the transport
    NetworkMessage.
  - Evidence verification — incoming announcements are validated.
  - MissingEvidenceRequest/Response — a request-response protocol for
    fetching evidence records a node does not yet possess.
  - Certificate evidence validation — a SlashingCertificate is only
    accepted once ALL evidence it references is present locally.

Known Issues
------------
1. Evidence sync currently operates on-demand (pull model).
   Peers do not proactively push evidence records; they only
   respond to MissingEvidenceRequests.  A push-based gossip
   optimisation is deferred to N112.

2. The MissingEvidenceResponse carries full serialised
   EvidenceRecords.  For large evidence payloads, a chunked
   transfer protocol may be needed.

3. Validator identity mapping (32-byte → 48-byte PublicKey)
   remains the temporary zero-pad solution introduced in
   N110.1b.

Future Work (N112+)
-------------------
- Push-based evidence gossip (proactive propagation)
- Chunked evidence transfer for large payloads
- Native 32-byte validator identity bridging N109 and amun-staking
- Evidence tombstoning / expiry for very old records
- Slashing certificate quorum (multi-signature certificates)
