Overview
--------
This baseline captures AmunChain at the moment the first provable
economic slashing pipeline was completed.  The system can now
detect validator misbehaviour, record it as permanent cryptographic
evidence, accumulate a weighted score, produce a verifiable
SlashingCertificate, propagate it through the network, embed it in
blocks, verify it during consensus, and execute the actual stake
reduction strictly after finality — with replay protection at
every level.

Known Issues
------------
1. CRITICAL LIMITATION: Evidence propagation is not yet
   network-wide.  Evidence records are created locally.  If a
   node does not witness the original misbehaviour, it will
   reject certificates that reference unknown evidence IDs.
   This is the largest remaining gap in the slashing pipeline
   and is the primary target for N111.

2. PublicKey in amun-kernel-types is 48 bytes, while N109/N110
   use 32-byte validator identifiers.  A zero-padding mapping
   is used temporarily.

3. No slash refund mechanism exists.  If a certificate is later
   proven invalid, restoring the slashed stake requires
   governance intervention.

Security Notes
--------------
- CertificateGossip deduplicates by certificate_hash before
  broadcasting.
- applied_slashing_certificates set prevents replay of the same
  certificate after finality.
- MisbehaviorRegistry prevents double-counting identical
  evidence IDs.
- Blocks with more than 10 slashing certificates are rejected.

Future Work (N111+)
-------------------
- Evidence gossip and sync between nodes (addresses the
  critical limitation above)
- Cryptographic validator identity unification between N105
  identities and staking registry identities (replace the
  48-byte / 32-byte zero-padding mapping)
- On-chain SlashingCertificate with quorum signatures
- Slash refund / fraud-proof pipeline
- Validator status propagation (warning → suspension → slash)
  through the network
