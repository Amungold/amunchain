# AMUN DESIGN PLATFORM

# USER EXPERIENCE CONSTITUTION

Version: 1.0

Status: FROZEN

Effective Date: 2026-07-01

---

# PURPOSE

This document defines the official
User Experience principles for every
product built on the
Amun Design Platform.

Every application SHALL provide
a consistent,
predictable,
accessible,
and understandable experience.

---

# UX PHILOSOPHY

The platform is built upon:

- Clarity
- Simplicity
- Consistency
- Predictability
- Explainability
- Trust

Users SHALL always understand:

- Where they are
- What is happening
- What happened
- What they can do next

---

# USER JOURNEY

Every workflow SHALL minimize:

- Clicks
- Waiting
- Confusion
- Repetition

Interfaces SHALL guide users naturally.

---

# CONSISTENCY

Explorer

Wallet

Studio

Governance

Developer Portal

All SHALL behave consistently.

Navigation,
terminology,
colors,
and interactions SHALL remain unified.

---

# NAVIGATION

Navigation SHALL always provide:

- Current Location
- Previous Context
- Next Available Actions

Breadcrumbs SHOULD be used
for hierarchical navigation.

---

# SEARCH

Global Search SHALL be available
from every page.

Recommended shortcut:

Ctrl + K

Search SHALL support:

- Blocks
- Transactions
- Addresses
- Validators
- Heights
- Hashes

---

# LOADING EXPERIENCE

Blank pages are prohibited.

Applications SHALL display:

- Skeleton Loading
- Progressive Rendering
- Real Progress Indicators
- Loading Feedback

---

# EMPTY STATES

Every empty state SHALL explain:

- Why no data exists
- What the user can do
- Suggested next actions

Empty screens SHALL NEVER
appear without explanation.

---

# ERROR EXPERIENCE

Errors SHALL include:

- Human-readable explanation
- Technical details (Developer Mode)
- Suggested recovery
- Retry action when possible

Silent failures are prohibited.

---

# FEEDBACK

Every user interaction SHALL
produce visible feedback.

Feedback categories:

- Success
- Information
- Warning
- Error
- Loading

---

# EXPLAINABILITY

Every important value SHALL
be explainable.

Examples:

- Block Height
- Hash
- Validator
- QC
- Constitution Status

The explanation SHALL include:

- Meaning
- Origin
- Calculation
- Importance

---

# COPY EXPERIENCE

Important technical values SHALL
support one-click copy.

Examples:

- Addresses
- Hashes
- Transaction IDs
- Validator IDs

Copy success SHALL be confirmed.

---

# RESPONSIVENESS

Applications SHALL support:

- Mobile
- Tablet
- Desktop
- Ultra-wide

No functionality SHALL depend
on a specific screen size.

---

# ACCESSIBILITY

Every interface SHALL support:

- Keyboard Navigation
- Screen Readers
- Focus Indicators
- Reduced Motion
- High Contrast

Accessibility is mandatory.

---

# PERFORMANCE PERCEPTION

Applications SHALL feel fast.

Strategies include:

- Skeleton Loading
- Optimistic Updates
- Lazy Loading
- Incremental Rendering

Perceived performance is important.

---

# KEYBOARD SHORTCUTS

Standard shortcuts SHALL remain
consistent across products.

Examples:

Ctrl + K

Global Search

---

Ctrl + /

Keyboard Shortcuts

---

F1

Documentation

---

Esc

Close Dialog

---

# VISUAL HIERARCHY

Information SHALL be prioritized.

Primary actions SHALL be obvious.

Critical protocol information SHALL
stand out visually.

Decorative elements SHALL NEVER
compete with important data.

---

# TRUST

The interface SHALL inspire trust.

Users SHALL never wonder whether:

- Data is authentic
- Actions succeeded
- Errors were ignored

Transparency is mandatory.

---

# COMPLIANCE

Products violating these UX rules
cannot be released as
Official Amun products.
